# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## Project Overview

Python PDF parser/converter: legal PDFs (acts, SEBI orders and circulars, eGazette notifications, judgments, amendments) become structured HTML (bluebell for `acts`/`sebi_circulars`) plus an IIIF manifest for `egazette`/`sebi`. It extracts text and coordinates, detects layout (headers, footers, sections, paragraphs, tables, figures) and applies document-type-specific rules.

## Rules that apply to every change

### Frozen areas - never touch without explicit user permission
If a document needs different behaviour: describe the cause, ask, then add a **narrow, generic rule alongside** the existing one (never replace it), keep thresholds relative/adaptive, and re-run the regression set to show every other output is unchanged. Do not rewrite, simplify, collapse, merge, reorder or "clean up" these, change their thresholds, or change what they emit.

1. **Judgment blockquote, `<pre>` and list logic**: `Main.detect_header_pre` (incl. `closing_match`, `first_prose_paragraph`), `Amendment.judgment_blockquote_v2` and everything it calls (trigger/italic/quote/list state machine, `plan_main_clauses`, `plan_section_headings`, list markers incl. Indic, paused lists, quotes inside items), `Page.detect_sparse_pre` (every grouping rule), and in `HTMLBaseBuilder.py` `split_rows_into_paragraphs`, `try_continuation_merge`, `local_gap_breaks`, `render_list`, `split_quote_sequence`, `parenthetical_continuation`, `closes_open_bracket`, the separator and glyph-bullet handling. Tuned against `judgment1/2/3/8/14/20/25/26/31/39/41/50/88` and `lu2fbRU1.pdf`; the user accepted that output, so those are the regression set (compare block structure and word content).
2. **Footnote, header/footer and image logic, every `pdf_type`**: header/footer (`Main.get_page_header_footer`, `adaptive_header_footer_detection`, `finalize_adaptive_header_footer_detection`, `_analyze_header_footer_content`, `_handle_single_page_header_footer_detection`, `_mark_related_header_footer_textboxes`, `_find_deep_header_groups`, `_extend_headers_footers_by_line`, `get_protected_running_headers_footers`, `_apply_adaptive_headers_footers`, `Page.line_based_header_footer_detection`, `label_header_zone_tbs`, `label_footer_zone_tbs`, builders' `add_header`/`add_footer`/`flush_pending_header_footer`); footnotes (`Main.get_all_footnote_text`, `Page.get_footnotes`, `get_referenced_footnote_nums`, `mark_standalone_footnote_markers`, `detect_footnote_blocks_by_style`, `_mark_standalone_footnote_citations`, `_mark_footnote_markers_in_tb`, builders' `_normalize_and_linkify_footnotes`, `arrange_footnote_sentences`, `render_footnote_section`, `strip_trailing_footnote_markers`); images (all of `Figure.py`, `Main.get_image_page_nums`, `finalize_unique_images`, `remove_empty_manifest_dir`, the `unique_images` pool and where image files are written).
3. **Multi-column page layout vs borderless-table detection** are two separate subsystems: `detect_multicolumn_layout` / `apply_column_reading_order` / `_count_narrow_columns` on one side, `get_borderless_table` / `BorderlessTableExtraction` / the continuation machinery on the other. Validated on `multicolumn.pdf`, `borderless_table.pdf`, `borderless_table2.pdf`.

### Standards for non-frozen areas
- **Table cells (`TableCell.py`)**: nothing outside a table may change. Check on two sets, committed source (`git archive HEAD source`, with `model/`, `machinelearning/`, `tools/` linked in, otherwise the font classifier is silently missing on the old side) vs working tree: the 19 table-bearing judgments of `test/test_judgment_pdfs` (`5, 8, 9, 17, 22, 27, 43, 44, 47, 48, 50, 53, 59, 62, 74, 76, 77, 85, 88`) and the 50 non-scanned egazette/sebi/default rows of `test/test_cases.csv`. (1) the html with each `<table>..</table>` replaced by a placeholder must be identical; (2) table text with tags/whitespace stripped may differ only where camelot's own text was wrong.
- **Sebi layout problems are fixed only in the sebi detection step** (`Main.process_pages_sebi` and the functions it calls, see "Sebi layout detection"), never in the frozen judgment functions.
- **`test/expected_html` is regenerated only when the user asks.** It is currently stale for everything touched by the `HtmlBuilderV2`/`BulletList`/table-cell/TOC work (see Testing).

## Core Architecture

### Main components

- **Main.py**: orchestrator (`Main`).
  - PDF -> XML via `ParserTool` (pdfminer) or `ChromeLensParserTool`/`TesseractParserTool` (scanned copies); dispatches type pipelines `acts`, `sebi`, `sebi_circulars`, `egazette`, `judgments`, default; runs `Page` objects; header/footer detection across pages (sequence matching).
  - `get_htmlBuilder` picks the builder per `pdf_type`: `HtmlBuilderV2` for `sebi`, `egazette` and the default type; `JudgmentBuilder` for `judgments`; `Acts` / `SebiCirculars` (bluebell) for `acts` / `sebi_circulars`; `HTMLBuilderChromeLens` is the OCR path. The old `HTMLBuilder` is kept but no type returns it. (Sentence-completion tuple variable is spelled `sentence_completion_punctutation` there - keep that spelling in edits.)
  - Writes the IIIF manifest (`Manifest.py`) for `egazette`/`sebi`.
  - Header/footer detection also runs for scanned `judgments`/`sebi` (`SCANNED_HEADER_FOOTER_PDF_TYPES`); other scanned types skip it.

- **ParserTool.py**
  - `parse_xml()` is the one place pdfminer XML is parsed. A `ToUnicode` hole (glyph -> U+0000) puts a raw NUL in the XML, which `ET.parse` rejects (killed a 31-page Mangal gazette). Plain parse first; only on `ParseError` strip XML-1.0-forbidden characters and retry; an unexplained `ParseError` is re-raised. An emptied `<text>` keeps its bbox and contributes no text.
  - **Deskew** (`Deskew.py`: `estimate_skew`, `rotate_image`, `straighten_pixmap`; called from `TesseractParserTool._ocr_pixmap` and `ChromeLensParserTool.process_page`): a slope of 1-3 degrees (`jsc3.pdf`) makes Tesseract drop justified paragraphs and makes textline boxes overlap, so `HTMLBaseBuilder` merges rows out of order. Angle = sharpest row-sum profile (coarse 0.5 degree search over +-5, then 0.05 refinement on a ~1000px copy); rotate only if angle >= `SKEW_MIN_ANGLE` (0.25) and sharpness gain >= `SKEW_MIN_GAIN` (1.2x), so straight scans are untouched (every scan in `test_cases.csv` measures 0). Rotation is about the centre on the same canvas, so xml coordinates stay page coordinates.
  - `ChromeLensParserTool._process_page_with_retry`: 5 attempts, backoff `attempt*5` s (5/10/15/20), the only backoff in the OCR chain. **No per-page catch anywhere**: a page that fails 5 times fails the **whole document** and discards earlier pages.

- **Page.py**: textbox processing, page layout, classification (headers, footers, sections, paragraphs, side notes, tables, figures); DBSCAN/KMeans clustering.
  - `detect_multicolumn_layout()`: KMeans on textbox x-centres, gated by column item-count/height-coverage/gap/overlap; gutter check is em-based; centred/full-width and rotated/vertical candidates are excluded. `_count_narrow_columns` makes it **fully adaptive** (cell-width cutoff = largest gap in this page's own distribution, alignment tolerance = median line height, decision `n_narrow_cols >= 2`), so a single-column page that merely contains a wide table is **not** multi-column. Skipped for scanned pages. `is_multicolumn` is authoritative for every consumer (`apply_column_reading_order`, `get_borderless_table`, `SentenceEndDetector`).
  - `apply_column_reading_order()` / `_reorder_by_columns()`: band-based order - all of the left column, then the right; only genuinely full-width items separate bands.
  - Borderless tables via `TableExtraction` when `-te`.
  - **`detect_sparse_pre`** (judgments and sebi, per page): unlabelled lines are split at wide gaps, grouped into rows, each classified `left`/`right`/`center` (>= `SPARSE_MARGIN_RATIO` 30% blank) or `gap`; consecutive aligned rows (`ALIGN_TOL_RATIO`, `MAX_GAP_HEIGHT_RATIO`) become `pre`. Additions that only ever add `pre`: centred lines of any width (`symmetric_center`, `weak_center`, kept only if half the rows differ from the group's position on *both* edges, so inset justified blocks stay paragraphs); aligned rows with nothing between (`nothing_between`, stacked judge signatures); mixed short rows with no sentence end (`SENTENCE_END_RE`, dandas included); rows on their own axis (`row_center`, signature blocks); a row continuing the block above (`block_above`); no mixed run starts on a paragraph's tail (`paragraph_tail`); "close" = the page's own line pitch (`tight_pair`). `-l debug` logs each group. Known gaps: a centred `title` line splits the stack; a textbox whose bbox runs off the page is skipped upstream (`judgment1.pdf` `(Rajesh Sekhri) (Sindhu Sharma)`).
  - `get_bulletins` (sebi only) and `get_titles` / `get_underlined_titles`: see Sebi layout detection.

- **HTMLBuilder.py**
  - `HTMLBuilder`: the original builder (sections, levels, `<h4>` titles, `-fn` via mark characters). No type returns it any more; Main never passed it `show_fonts`/`detected_fonts`.
  - **`-fn` in `HTMLBuilder`**: the font is carried as a mark in the text (`TextBox.FONT_MARK_START/END`, noncharacters), never as markup, because the builder reads text to decide structure; everything that reads goes through `plain()` (`strip_font_marks`), `render_font_spans()` turns marks into `<span data-font=.. data-detected-font=..>` once on the finished html. `lsdebate.pdf` covers it.
  - `HTMLBuilderChromeLens`: OCR output path with its own word-level gutter detection (`_detect_word_columns`, `_split_row_by_column`, `_reorder_rows_by_column`).
  - **`HtmlBuilderV2`** (last class of the file, `class HtmlBuilderV2(GlyphBulletLists, HTMLBaseBuilder)`): the builder for sebi/egazette/default. All paragraph/merge/list/`<pre>`/blockquote/table/footnote/TOC logic is `HTMLBaseBuilder`'s own code, **inherited, not copied**; the subclass adds only what these pages produce and judgments never do and never edits the frozen functions. Same constructor as `HTMLBuilder`. `process_pages_sebi` and `process_pages` set `doc_line_gap` / `doc_max_line_width` on it. Verified on `sebi1-5.pdf`, `changeofnames.pdf`, `gazette1.pdf` (no `<div>`/`<pre>` in cells, no stray markers, no `<fontrun>` left).
    - **Labels**: list labels (`["amendment"]`, `["amendment","title"]`) and `('italic','blockquote')` are blockquotes, other tuples paragraphs (`tag_for_label`). `"side notes"` textboxes are removed for the build and written afterwards as hidden `<span class="side-note-text">`.
    - **Titles are `<h4>`** (`emit_title`): still goes through `emit_paragraph(.., is_heading=True)`, so the judgment heading logic decides (a title that completes a sentence or continues the item above stays `<p>`); a surviving heading is rewritten `<p>` -> `<h4>`. A title block as wide/tall as body text (`TITLE_PREAMBLE_*_RATIO`) is a paragraph.
    - **`levelN` labels keep ONE open list** like `HTMLBuilder.addLevel` (`render_level_items`, `open_level_item`, `close_level_stack`, `_level_stack`): `level1` is a `<p>` and closes the list; `level2+` (`("level", n-2)`) open `<ul><li>` that **stay open across blocks and pages** (deeper = nested `<ul>` inside the `<li>`, same = sibling `<li>`, shallower = close deeper). Text, quotes, tables and `<pre>` arriving while an item is open land inside that `<li>` (wrapped sentences merge via a `li` merge anchor, `level_item_anchor` + the `li` branch of `append_to_anchor`). Closes on `level1`, a title (unless it continues the item), a `Date:`/`Place:`/`Sd/-`/"Judgment pronounced" row (`LEVEL_CLOSE_RE`, copied from `HTMLBuilder.addTitle`) and end of document. The first line of each level textbox gets `bq2_start="1"` (`mark_item_start`). **Rendering each level textbox as its own `ul` block gave `<ul><li>..</li></ul><ul>..` runs and was wrong.** `ul { list-style-type: none }` comes from the inherited css.
    - **`-fn` here**: `build_styled_line_text` puts a `<fontrun N>` tag in the *styled* text at every font change and line start (plain `value` never sees it; `unit_style_signature` strips it); `get_html` -> `render_font_runs` wraps each text stretch between tags in `<span data-font=.. data-detected-font=..>` before `finalize_toc` (a font carries through plain block tags, `sup`/`a`/`span` are isolated, whitespace-only stretches left bare). `Main` passes `show_fonts`/`detected_fonts` (`Main.detected_font_classes`) only to V2. Pre blocks and table cells are not annotated.
    - **Smaller additions**: `pre_continues_paragraph` (a `pre` starting lowercase after an unfinished paragraph is rendered as `p`); `front_heading="1"` textline attribute (set by `Main.detect_sebi_front_matter`) pulled out of a front-matter `<pre>` as `<h4>`; `arrange_table_cells` also runs `apply_table_footnote_markers`, and the footnote linkifier understands `{{^{{FOOTNOTE n@page}}}}`; `column_switch_ends_paragraph` ends a paragraph at a column jump on an `is_multicolumn` page (only ever adds a break).

- **Judgment.py**: `JudgmentBuilder(GlyphBulletLists, HTMLBaseBuilder)`, what `judgments` uses (a bare subclass; the base `HTMLBaseBuilder` in `HTMLBaseBuilder.py` is untouched).
- **BulletList.py**: the `GlyphBulletLists` mixin, shared by `JudgmentBuilder` and `HtmlBuilderV2`. `emit_paragraph` tags a glyph-bullet paragraph (`starts_with_bullet_glyph`: `•`, `▪`, `✓`, `➢`, any `BULLET` name, private-use such as U+F0B7) with `﷓<x0>|<height>﷔` before its styled text (decisions use the plain text, so merge logic is unchanged); `close_html` rewrites each run of adjacent marked `<p>` as nested `<ul><li>` (`convert_bullet_runs`, `bullet_depths`: x0 differing by more than a line height = deeper), keeping the glyph and removing all markers. **A bullet whose text after the glyph is entirely bold/italic/bold-italic stays `<p>`** (`bullet_text_is_styled`); a bullet that merely starts with a bold label stays in the list. Bullets inside `<blockquote>` untouched. Inside an open sebi `level` item they nest under that `<li>`. Checked over the 14 regression judgments: ten byte-identical, the four with bullets (`3, 8, 34, 88`) differ only by `<p>• ..</p>` -> `<ul><li>• ..</li></ul>`.

- **TableCell.py**: `TableCellArranger`, a mixin of `HTMLBaseBuilder` and `HTMLBuilder` (egazette/sebi/default/judgments; not `acts`/`sebi_circulars`, the OCR builder or scanned copies). It rebuilds a bordered (camelot) table's cell text from the pdf's own characters; camelot supplies only the grid (`TableExtraction.cell_grids`) because its text puts a line across columns into one cell, breaks words, invents glyphs and flattens layout. Frozen logic is not involved.
  - **Content by coordinates** (`arrange_table_cells`, `collect_cell_chars`, `group_segments_into_lines`, `layout_lines`): each character goes to the cell its centre is in; segments cluster into lines by vertical centre; bold/italic/underline via `get_char_style`. Placement uses tolerances in character widths: dominant left/right edges (`dominant_edge`) classify lines `full` / `short` / `indent` / `right` / `center`. A cell whose lines share one centre or right edge is one label paragraph. In a block with >= 2 `full` lines and body >= `MIN_PRE_BODY_CHARS`, a run of short/centred/right lines containing a centred or right-aligned one is a `<pre>` at real offsets (`render_pre`: `--Applicant` / `Versus` / `--Respondent`, signatures). Everything else flows into paragraphs starting at a list marker, after a short line of a justified block, or after a gap > `PARA_GAP_RATIO` pitches. Internal form: `<div>` paragraphs (never `<p>`, which `finalize_toc` would take as a heading candidate - `judgment47` heading XII) and `<pre>` runs.
  - **A number-and-dot line is not always a new paragraph** (`NUMBER_MARKER_RE`): `773.` in `(2021) 10 SCC` / `773. Para 3` no longer starts a paragraph when the line above is `full`, does not end a sentence and the number is not the successor of the cell's last number marker (first must be `1`). `(a)`, `(i)`, `•` and markers after a finished sentence behave as before.
  - **Safety nets**: spanned cells, rotated text (mostly single-char lines, several lines), tables with footnote markers keep camelot's text; a rebuilt cell with fewer word characters than camelot's is reverted unless the whole table lost nothing.
  - **Overprinted glyphs** (`is_overprinted`, `OVERPRINT_*`): twin glyphs (same glyph, >= 70% box overlap; zero-width marks within `OVERPRINT_MARK_TOLERANCE` line heights) are removed **only** when >= half of a line's glyphs are twins. The line condition is mandatory: geminates (`ತ್ತ`) and adjacent narrow letters (`(iii)`) overlap like overprints (`tamil-marutham.pdf`, `marathi-sakal.pdf`).
  - **Header row** (`register_header_row`, `has_header_row`, `promote_header_row`): first row of a table with >= 2 rows and columns becomes `<thead><th>` when all bold while the body isn't, or median glyph height differs by `HEADER_SIZE_RATIO` (15%). Remembered by content, recognised after pages merge.
  - **Cell cut by a page break** (`merge_tables`, `continued_column(.., cut)` -> `(column, glue)`, `join_cell_html(.., glue)`): a first row filling only the single column the previous last row filled is the same cell. Old rule (still used for `same_page` / `cross_page_header`): join only if the tail has no sentence terminator and the head is not a marker. New: when the previous table reaches the bottom band and the next starts in the top band (`_table_adjacency` override records `table_cut_by_page`) and the table has >= 2 columns, merge even after a finished sentence or before a marker (`(A) Offences..`, `7. The learned..`); `glue` joins the two paragraphs into one sentence only under the old condition, otherwise the continuation becomes a new block of the cell. Camelot tables only (`table2_bbox` given). `judgment9.pdf` and `Mohmmad_Nasir_vs_State_Of_Uttarakhand_on_1_October_2026.pdf` are one row.
  - **Written cells carry no `<div>`/`<pre>`** (`flatten_cell`, `flatten_table_cells`, called by `HTMLBaseBuilder.addTable` and `HTMLBuilder.get_table_cell_text`): blocks separated by a line break (`&#10;`, kept by `white-space: pre-wrap`), `<pre>` indentation kept as spaces, `<b>/<i>/<u>` kept, plain tail text left after the last block (boundary merge) joined with a space. `has_header_row` is asked before flattening.

- **HTMLBaseBuilder.py**: `HTMLBaseBuilder(TableCellArranger, TableBuilder)`, the base of both `JudgmentBuilder` (`-t judgments`, Judgment.py) and `HtmlBuilderV2` (sebi/egazette/default); `split_rows_into_paragraphs` splits rows on a marker row, a style change or a larger-than-normal gap after a sentence end, `try_continuation_merge` re-joins mid-sentence groups. Generic, layout-driven additions (all only ever *add* a break unless stated):
  - **Tables**: `build()` runs `arrange_table_cells`; `addTable` emits a remembered header as `<thead>` and flattens cells; `merge_tables` wrapped (see TableCell). In `build`, a `figure` whose image is not in `unique_images` (deduplicated/junk, nothing written) is skipped before the pending-table flush, so it never breaks table continuity across pages (`ORDER_1791957080.pdf` annexure, pages 60-77, a repeated corner logo on every page); an emitted figure still ends the pending table. `SebiCirculars` already skipped such figures; `Acts` never receives figures (`Page.sort_all_boxes` returns before merging them for `acts`). Borderless tables not run for judgments.
  - **Indic paragraphs** (`indic_layout_starts_paragraph`): when either line has an Indic letter and the previous ends a sentence (`।`/`॥`/`۔` always; `.` via the abbreviation check), a new paragraph starts at a first-line indent >= `INDIC_INDENT_RATIO` (0.6) line heights past the block's 10th-percentile x0, or in a justified block (`block_is_justified`, >= `JUSTIFIED_BLOCK_RATIO` of non-final lines reach the right edge) after a short line (`judgment31.pdf`).
  - **Enumerated items** (`enum_item_starts`, `ENUM_MARKER_RE`, `ENUM_ALIGN_RATIO`): consecutive markers at one left edge (`(x)`->`(xi)`, `(a)`->`(b)`, `1.`->`2.`, `i)`->`ii)`; `(i)` read as roman and letter) each start a paragraph; flagged `enum_item_start`, `anchor_enum` stops `try_continuation_merge` gluing the next item (`continues_enum_list`), across blocks/pages (`enum_follows_history`, `_enum_history`, `enum_same_list`). Decimals, years, `(SC)` never markers (`judgment27`, `judgment50`).
  - **Hanging-indent continuation** (`hanging_continuation`): after a full-width marker row with no end punctuation, a more-indented next line continues it.
  - **Paragraph end at a page break** (`page_break_ends_paragraph`): a short line ending in boundary punctuation at page bottom ends its paragraph if the next page's line starts at a clearly different left edge or the block is justified and the line completes a sentence.
  - **Lists** (`tag_for_label`, `render_list`, `split_at_inline_markers`): `list:D` -> `("ul", D)`, tag per line from `line['bq2']`; nested `<ul><li>`, items start on `list_start`, depth change or separator row; marker text stays in the `<li>`; `ul { list-style-type: none }`.
  - **Separator rows** (`is_separator_text` -> `Utils.is_separator_line`) stand alone (`****`, `.....`, `xxx`, `---xxx---`, script-independent).
  - **Blank-line paragraphs** (`local_gap_breaks`, `BLANK_LINE_RATIO`, `gap_break`): a row whose gap above is a local blank line (smaller neighbour tighter than the document's normal spacing) starts a paragraph and is never glued back; `closes_open_bracket` / `CLOSING_TOKEN_START_RE` stop `VII) Comp.` after `(Med.` being a marker (`judgment25`, `judgment1`).
  - **Bare number after a parenthesised abbreviation** continues the sentence (`parenthetical_continuation`, `append_to_anchor`; `…1993 (Suppl.)` / `2 SCC 419`, `judgment3`).
  - **Run-in sequences inside a quote** are split into one `<blockquote>` per item (`split_quote_sequence`, `after_clause_break` -> `Utils.follows_clause_break`; needs >= 2 items, `judgment20`).
  - **Glyph bullets start their own paragraph** (`is_glyph_bullet`; hyphen and middle dot are deliberately not bullets; `judgment34`, `judgment88`). BulletList.py turns the resulting `<p>`s into lists.

- **Acts.py / SebiCirculars.py**: bluebell builders (`TableBuilder` + `SentenceMaker`).

- **Amendment.py**: amendment and blockquote detection.
  - **Per-section body margin** (`recurring_page_margins`, `leftmost_supported_left`, `body_margins`): a page's margin is its leftmost well-supported left edge; it counts as a section margin only as the leftmost of a contiguous run of >= `max(3, 10% of pages)` pages; a page uses its run's margin only when `doc_margin` is absent from it (`judgment8` pages 13-49 at x=156 vs 113.4; `judgment50` scattered quote pages never form a run).
  - **First-line indent is not a quote** (`first_line_indent`).
  - **`judgment_blockquote_v2`** is the judgment blockquote/list detector (judgments only now; `check_for_blockquotes_judgments` is called by nothing active). Per *row*; writes `bq2` (`p`/`blockquote`/`list:D`), `bq2_start`, `bq2_inline` onto textline elements (`Table.extract_textlines` copies them); a textbox takes the label of its first non-`p` line. Layout/Unicode rules only. State machine `bq2_mode` = `None`/`italic`/`list`/`quote`:
    - **Trigger** (`BQ2_TRIGGER_RE`: `:`, `:-`, `:—`, `;-` + optional opening quote) arms the next row: fully italic row (`textlines_italic`, `BQ2_ITALIC_RATIO`) -> italic mode; value-1 list marker -> list (wins when the marker is not italic, `marker_italic`); other marker/number or indented opening-quote row -> quote; nested lists inside quotes resume the quote after.
    - **Main paragraph tracking** (`parse_main_clause`, `is_next_main_clause`, `main_clause_shift`): follows the court's numbering (`1,2,3`, `3.1`); a main number closes any mode; never when the previous row ran to the right edge mid-sentence (`prev_midsentence`).
    - **Numbering plan** (`plan_main_clauses`, run after `compute_document_margin`): walks aligned candidates in document order, accepting a number that succeeds the last, or a restart/skip when the next aligned number succeeds it; a candidate right after a trigger can't restart; never overrides an open list (`list_continues`); a planned number closes italic mode (`judgment25`). The main column is the court's own numbering (the one with a run `1., 2., 3.`), not merely the densest - unless the densest holds the run's successor (`judgment41` quotes other judgments' numbering; `judgment47` shifts x). Indic digits count.
    - **Section headings** (`plan_section_headings`, `BQ2_SECTION_RE`): short roman-numeral row is a heading only if it continues the heading chain **and** main numbering restarts after it (`restarts_after`; keeps `judgment3` `III. Ethanol` in its quote).
    - **List stack** (`bq2_list_stack`, `parse_list_marker`, `list_follows`): readings `(kind, style, case, value)`; sibling pops, value-1 of a new kind pushes; markerless rows continue the item if the previous row is open, ends with a trigger, is indented, or flows on (`flows_on`). Inline markers via `find_inline_markers`. Indic letters/digits via Unicode blocks (`script_letter_readings`, step 1 or 2 for skipped letters); multi-character syllable markers stay text.
    - **Paused lists** (`suspend_bq2_list`, `resume_bq2_list`), **quotes inside items** (`quote_unclosed`, `bq2_quote_in_list`), **capitals headings** (`is_caps_heading`, >= 85% uppercase), **line spacing** (`document_pitches`, `pitch_class`: tight = <= 1.25 x the larger of the class pitch and the page pitch), **separator rows** transparent inside open modes.
    - `-l debug` traces every decision (`blockquote_v2 .. opened/closed/resumed`, `main clause`, `plan skipped`, list-close geometry).
  - `check_for_blockquotes_judgments` guards (kept for reference): a row at the body margin is never "indented"; a closed quote re-opens on a marker row at or beyond its indent.
  - `check_for_italic_blockquotes_sebi`: see Sebi layout detection.

- **TableExtraction.py**: camelot lattice tables and borderless detection with online-RL logistic classifiers (`PenalizedLogisticClassifier`, `HeaderRowClassifier`, `RegionMergeClassifier`, `ContinuationClassifier`; REINFORCE-style `reinforce()`, reward = downstream `fill_ratio` / shortfall penalty; fixed default weights every run, nothing persisted).
  - **Bordered tables keep their grid**: `TableExtraction.cell_grids` = `{id: [[(x1,y1,x2,y2,spanned)..] per row]}` in pdf coordinates, row 0 on top (not named `table_cells`, which `Page.label_borderless_table_tbs` already reads).
  - **Cross-page continuation**: `_compute_continuation_out()` emits a column template when a table covers >= 30% of the page (`continuation_page_coverage`), sits in the bottom margin (`continuation_bottom_margin_ratio`) or has a column-ruler row (`(1)(2)(3)..`, `_table_has_column_ruler`); `Main.pending_continuation` threads it forward. With a template, `get_table_and_bbox` runs `_detect_continuation_table()` **first** (`_suppress_normal_tables_within` / `_in_span` drop mis-splits); rows by top edge (`_rows_by_top`), band-based inclusion (every item of an included row is kept), large gaps are paragraph breaks, stops on `continuation_max_skip_rows` out-of-band rows or a section-sized gap; accepted by `ContinuationClassifier` (coordinate features) gated by `continuation_top_band_ratio`, `min_cols`, `continuation_min_fill_ratio`.
  - **`ColumnTracker`**: running count-weighted x0/x1 per column (drift absorbed), tolerance only widens; recurring unmatched "orphans" promote to a new column only if disjoint from tracked columns (so `(A)/(a)` markers inside a free-text cell don't); strays go to the nearest column; `_recover_unassigned_items` is an iterative flood-fill.
  - **Labelling by source box**: `table_item_objs` -> `("borderless_table", idx)` for exactly the boxes the dataframe was built from.
  - **Reclaim passes** (`reclaim_header_footer_for_continuation` with an incoming template; `reclaim_header_footer_within_bbox` after a no-RL probe pass `rl_enabled=False`) give back header/footer/side-note boxes that fall inside a table.
  - **Spine tables**: `_select_spine_column` prefers a much larger clean column (>= 2x) over a corroborated sparse pair; `_has_spine_column` (>= 80% of rows) relaxes `_prune_weak_columns`, `_passes_multi_col_row_check`, the accept gate (`min_fill_ratio_with_spine`) and `_trim_non_tabular_edge_rows` (stray only if >= 75% wide, <= 2 rows per edge).
  - **Template propagation is a union** (`_continuation_out_from_tables`, `_merge_column_ranges`, ranges from `ColumnTracker` averages); **passthrough** (`continuation_passthrough`) keeps the chain alive across single-column overflow pages.
  - Validated on `borderless_table2.pdf` (ruler-seeded schedule) and `borderless_table.pdf` (no ruler).

Out-of-order asks fall back to `extract_one`; `-sc` returns before any of it.

- **FontStyle.py**: `FontStyleReader` decides once per document which fonts are bold/italic; `Main.annotate_font_styles` writes `fstyle` (`b`/`i`/`bi`) on every glyph. Signals: font name, descriptor (`ForceBold`, `/FontWeight` >= 700, `Italic`, `/ItalicAngle`), embedded program, pymupdf span flags. For TrueType/OpenType the `OS/2` table outranks `head.macStyle` whenever `fsSelection` makes a claim (`OS2_STYLE_BITS`; `judgment39/68` had 92-93% `<b>`). Fake bold/italic (double-struck, slanted matrix) is not detected.

- **Utils.py**: `is_separator_line` (+ `SEPARATOR_*`), `is_bullet_glyph` / `starts_with_bullet_glyph` (skips leading `<b>/<i>/<u>` and font marks), `split_at_bullet_glyphs` (cuts before a bullet that follows whitespace), `follows_clause_break` / `is_word_token` (Unicode `Po`/`Pd`, so `।` counts).

- **FontSurvey.py** (standalone, not in the pipeline): inventories fonts across PDFs. Per page it merges `get_fonts(full=True)` (declared) and `get_text("dict")` spans (drawn); ids = base name without the subset prefix; ranked by documents that genuinely *draw* the font; file list ordered by the font's share of each document's words (`FontRecord.get_file_shares`, JSON `drawn_file_shares`). `-i` accepts directories, files and wildcards (quote a pattern so the tool expands `**`; `~` expanded; `-r` recurses; matches deduplicated). A legacy indic font shows as latin gibberish + `no tounicode` -> needs `-fc`.
  - **Training-corpus mode** (`-tf LABEL=REGEX`, `-nf REGEX`, `-tc` csv, `-tw` words per sample, default 50): one csv, one row per sample `label,font,pdf,text` (`TrainingWriter.CORPUS_FIELDS`), the single source `machinelearning/features.py` trains from; both tools name a file (`training_data/samples.csv` default), not a directory. A sample = `-tw` words of one font (buffered per font, `flush()` per document; CA 0.938 -> 0.993 vs one run per sample). Text from a font matched by neither regexp is **dropped** (reported by `get_dropped_report()`), never defaulted into `not_required`. Labels `[A-Za-z0-9_-]`; `not_required` rejected as a `-tf` label; both `-tf` and `-nf` required with `-tc`. Unit of text = a `get_line_runs()` run. Type3 fonts are a class (`-tf type3='^type3'`; broken `ToUnicode` repaired by `ToUnicodeFixer.fix_type3_fonts`).

- **machinelearning/** (Orange3): learns which decoder a font needs from its extracted text. `features.py` (every 1-5-word phrase counted, top 10,000 as features, whitespace tokenization, deterministic ties, singleton pruning at 2M keys, classes under `min_samples` dropped); `training.py` (`-c` corpus, `-m` model, `-k` folds, `-le` learners, `-fl` final learner, `-mc` cap per class, SGD `max_iter=1000`, confusion matrix from `results.actual/predicted`); `predict.py` (`FontClassifier(model).classify(text)` -> `(label, probability)`; classify as much text of one font as available). `Main.detect_unknown_fonts` is the pipeline's caller. See `machinelearning/README.md`.

### Sebi layout detection - `Main.process_pages_sebi` and what it calls
Order: `compute_document_margin`; per page `Amendment.check_for_italic_blockquotes_sebi`, `detect_sparse_pre`, `Page.get_bulletins`, `get_titles`, `get_underlined_titles`; then `doc_line_gap` / `doc_max_line_width`. `judgment_blockquote_v2` + `plan_main_clauses` were tried and **reverted** (they closed a list after an item's first row); `check_for_blockquotes_judgments` is no longer called by anything active. `detect_header_pre` stays judgments-only (its `ORDER`/`JUDGMENT` tiers end a sebi caption too early).
- **Blockquote = italic text after a lead-in** (`check_for_italic_blockquotes_sebi`, state `sebi_quote_state`): a plain textbox ending in `:` or `;` (plus dashes) arms it; the next italic non-bold textbox opens a quote and every following italic textbox continues it (across pages, labelled headers/footers skipped) until the first non-italic one. A bold heading <= 120 chars between lead-in and quote keeps it armed and stays a title; a bold-italic textbox opens a quote only if followed by an italic one, else it is a title (`Table 1 Summary..`). **A table disarms and closes it** (`sebi5` `*The figures are an aggregation..` notes). Regular-type quotes are deliberately not blockquotes. Italic = `TextBox.is_italic_or_oblique` (sebi fonts are `Helvetica-Oblique` / `Helvetica-BoldOblique`).
- **Bold/italic bullet-like lines are titles, not levels** (`Page.get_bulletins`, sebi only): mostly-bold (`textFont_is_bold('sebi')`) or italic textboxes are skipped, so `15.1. Whether..?`, `A. Whether..`, `Step 1:` reach `get_titles`. Numbering fixes: a line merely starting with a number (`21, 2020, at 03:15 P.M.`) is not a marker (token must end in `.` or `)`; it used to reset depth and drop `b.`/`c.`), and a single capital + `.`/`)` is a marker (`A.`/`B.`; `C.`/`D.` matched only as roman numerals).
- **Front matter** (`Main.detect_sebi_front_matter`, called in `get_page_header_footer` right after `detect_toc`): the caption (reference no., `ORDER`, `Under Section..`, `In respect of:`, parties, `In the matter of..`) = every unlabelled textbox above the first body start = the first value-1 numbered row (`1.`, `1)`, `(1)`; `\d`, so Indic digits) that is prose (full width or followed by a full-width row; a party list `1.  JSI Investments` is not) or the first `toc`-labelled textbox. They become `pre_header`. A one-line heading directly above (colon-ended, mostly capitals, or bold and < 30% of text width) stays out and is labelled `title`; sharing a textbox with the caption (`sebi1` `Background`) it gets `front_heading="1"` and V2 writes it as `<h4>` after the `<pre>`. No numbered prose paragraph and no toc -> nothing marked. A bordered table lying wholly above the body start (the `In respect of:` party table) is flattened into the caption `<pre>` (`Main.flatten_front_matter_tables`: its textboxes become `pre_header`, its camelot table is dropped; a table that reaches into the body is untouched); a note line just under the table's bbox that was mislabelled as part of it is read as caption text again (`sebi5`).

### Order sheets and tables of contents
- **Order sheets** (`Main.unwrap_table_document`, judgments only, in `get_page_header_footer` right after per-page table labelling, before header/footer detection): when **every page with text has >= half its textboxes labelled `("table", id)`** (measured: 100% on every page of `judgment9.pdf` and the Mohmmad Nasir pdf, 0% on most pages of every other judgment tried), the table is a layout frame: the first row of a >= 2-row table is the column header if all its cells have text and the next row has an empty one (the cell grid gives its band) -> `header` (hidden span); every other table textbox returns to `None`; the page's camelot `tables`/`table_bbox`/`cell_grids` are cleared; the normal judgment pipeline then runs unchanged. Nasir -> front-matter `<pre>`, paragraphs 2-8, 15 `<blockquote>`s for the quoted guidelines, closing `<pre>`; `judgment9` -> `<pre>`, paragraphs, `(i)-(iii)` list. Limits: a page mixing paragraphs with a table doesn't trigger it; frozen-logic misses still show (`judgment9` paragraph 8 tail as a sparse `<pre>`).
- **Tables inside the judgment header pre** (`Main.flatten_pre_header_tables`, judgments only, called right after `detect_toc` and never inside the frozen `detect_header_pre`): a camelot table with `pre_header` text both above and below it (reading order, page then y) is written as part of the `<pre>` - its textboxes become `pre_header`, its table/bbox/cell grid are dropped (`flatten_table_into_pre_header`, shared with the sebi front-matter step). It must run after `detect_toc` so an INDEX table already labelled `toc` is skipped (run before it, `judgment47` lost its 52-entry contents list). A table that is the first thing on the page or has no pre text after it stays a table. Checked on the 19 table-bearing judgments: 9 flatten at least one table (`5, 17, 47, 48, 50, 53, 74, 76, 77`), the other 10 are untouched; word content is unchanged except `judgment50`, which regains a heading line the table had swallowed.
- **TOC read from a table** (`Main.detect_table_toc`, `toc_entries_from_tables`, judgments only): when the dot-leader path finds no heading or < `MIN_ENTRIES`, the heading is looked for among unlabelled *and* `pre_header` lines and following camelot tables are read in page order while >= half their rows end in a page reference (`\d{1,4}` + optional connector + second number) with something besides a serial number; rows become level-1 `toc_entries`, heading and table textboxes become `toc`, `finalize_toc` renders `<nav class="toc">` (`judgment47.pdf` `INDEX`). Other types and working dot-leader TOCs take the old path.
- **TOC back-links** (`TableBuilder.finalize_toc`, `Table.py`, all builders): contents rows pointing at a heading get `id="toc-entry-N"`; the heading ends with ` <a class="toc-backlink" href="#toc-entry-N">↩</a>` (the footnote arrow), placed after the heading text and any footnote marker, before a nested list (`toc_link_length`); none when the heading starts with a hidden span or its `<b>/<i>/<u>` don't balance before the cut, nor for a second entry matching an already anchored block. Forward links (`#toc-anchor-N`) unchanged. Entry text and the title go through `NormalizeText` in `finalize_toc`, like the body (PUA bullets such as U+F0B7 become `•`, curly quotes straight; `judgment88`); a PUA character missing from `NORMALIZE_MAP` stays as drawn.

### Key Processing Pipeline

1. PDF -> XML (pdfminer, or ChromeLens/Tesseract for scans); `drop_overlapping_spaces`, `detect_unknown_fonts`, `convert_indic_fonts`, `annotate_font_styles`, watermark marking.
2. Per page: textboxes, figures, table labelling (+ `unwrap_table_document` for judgments).
3. Header/footer detection across pages; footnotes; multi-column detection (every `pdf_type`) and column reading order; borderless tables (`-te`, not for judgments); `detect_repeating_tables`; `detect_header_pre` (judgments); `detect_toc` -> `detect_sebi_front_matter` (sebi).
4. Type-specific pipeline (`process_pages_acts/_sebi_circulars/_sebi/_judgments/process_pages`).
5. HTML build by the per-type builder; IIIF manifest for `egazette`/`sebi` with a link injected into the HTML.

### Caching System
- `cache_xml/`: `<pdfname>-<run_id>.xml`. `cache_pdf/`: `<run_id>/tounicode/<pdfname>.pdf` (repaired copy), `<run_id>/<pdfname>.pdf` (copy of an input without the `.pdf` suffix), and `cache_pdf/.runs/<run_id>` liveness markers. Cleaned automatically unless `-x/--keep-xml`.
- **Cleanup is anchored to the `Main` instance** (`cleanup_run(keep_xml=None)`: `clear_cache_pdf`, `clear_xml_cache` (skipped when keeping), `clear_camelot_cache`, `clear_ocr_engines`, each wrapped and idempotent). Every `Main.__init__` calls `_register_run` (weakref in `_active_runs`); one `atexit` `cleanup_active_runs` covers normal exit, exceptions and `Ctrl-C`; `SIGTERM` needs `install_cleanup_signal_handlers` (CLI installs `SIGINT`+`SIGTERM`; a `ProcessPoolExecutor` must pass it as `initializer`; `TestPdfToHtmlDiff` does and calls `main.cleanup_run()` in `finally`). Covered by `test/TestCleanup.py`.
- **Hard-killed runs are reclaimed by the next run** (`sweep_orphaned_cache`, `_write_run_marker`, `_protected_run_ids`): each `Main` writes `cache_pdf/.runs/<run_id>` (pid + keep flag) before any cache file; the first `Main` per process (`_sweep_once`, also `setUpClass`) deletes `cache_xml/*-<run_id>.xml` and `cache_pdf/<run_id>/` whose pid is dead and not kept. Pid reuse fails safe; an `-x` run leaves a `keep_xml=1` tombstone.
- **Every cached file is named for the run** (`Main.run_id`, `get_run_cache_pdf()`): documents routinely share names (every weekly gazette has a `9.pdf`) and the egazette `pdf2html` pool would otherwise interleave or delete each other's files. PDF copies keep the document's basename inside the run dir because output names come from `self.pdf_path`.

## Development Notes

- The system is coordinate-based: textbox positions determine classification. Header/footer similarity uses `SequenceMatcher` at 0.4. Multi-column detection runs for every page before hierarchy detection and is a pure reading-order fix. Amendment detection is a specialised legal-document feature.
- **Overprinted-space removal** (`Main.drop_overlapping_spaces`, right after `get_pages_from_xml()`, before `convert_indic_fonts` and layout): a space glyph that never advances the pen is entirely inside (`SPACE_OVERLAP_RATIO = 0.95`) the x-range of the nearest real glyph and is removed (Devanagari `िभन् न` -> `िभन्न`). Full containment, not overlap, because kerning pulls a letter ~0.6 over a space; neighbours are the nearest non-space, non-zero-width glyphs; skipped when the two neighbours overlap each other by > `NEIGHBOUR_OVERLAP_RATIO` (0.1) (rotated watermarks).

### Legacy indic font conversion
`Main.convert_indic_fonts` (right after `get_pages_from_xml()`, before layout): a `<text>` whose `font` matches an `indic2unicode` converter key (`re.search('.*<key>.*')`, case-insensitive) is rewritten in place over the longest run of consecutive same-font chars, spread back proportionally keeping each bbox.
- **Matching**: `get_indic_font_res` tries converter keys **longest first** (`.*nudi.*` would otherwise swallow `Nudi01k,Bold`, whose kannada-digit converter differs). `INDIC_FONT_NAME_ALIASES` adds other names (`krutidev` <- `kruti[\s_-]*dev`, `vivek`, `dev[\s_-]*lys`; `tamelango` <- `tam[\s_-]*elango`, `tam[\s_-]*vanavil`; `tmchanakya` <- `tm[\s_-]*chanakya`); `INDIC_FONT_NAME_PATTERNS` keeps pairs apart: `nudi(?![\s_-]*uni)`, `chanakya` not preceded by `TM`, `revathi` not preceded by `TT` (`ttrevathi` is the TrueType build), `vanavil` not preceded by a layout word, Noto Serif Malayalam only when the name starts with it (`NOTO_SERIF_MALAYALAM_PATTERN`, Regular excluded).
- **Names often don't reveal the encoding** (`union_hindi.pdf` `TT572t00`/`TT447t00` are chanakya): that is what `-fc` and the font classifier are for.
- **`(cid:N)` fallback** (`CID_PLACEHOLDER_RE`, `CID_FALLBACK_FONT_KEYS`, `get_indic_char_text`): a glyph with no `ToUnicode` entry is read as `chr(cid)` **only for `tunga`** (its cids are the codepoints its converter has tokens at; 209 glyphs in `kannada-tunga.pdf`). Not a list to widen: in ordinary subset fonts the cid is an arbitrary glyph id and handing it to a converter drops the character (`judgment59` lost a reph). `get_cid_fallback_font_keys()` widens the set to the converter's other keys by object identity.
- **`nirmalaui` reads devanagari only** (`CONVERTER_SCRIPTS`, `get_converter_scripts()` / `is_converter_script()`): `convert_indic_font_runs` ends a run at a glyph of another indic script and leaves it as drawn; `get_detected_font_key()` points a `nirmala` verdict at it only when <= `FONT_DETECT_MAX_INDIC_RATIO` of the text is another script. A repaired Nirmala UI goes to `nirmalaui_glyphs`, which splits by script. `arialuni` has the same limitation (not in the table).
- **Per-font notes** (all covered by a case in `test_cases.csv` and a fixture in `indic2unicode`'s own `testdata/`):
  - **Tunga** (kannada): unicode font with a sound map but drawn-order text; the converter reorders (`kannada-tunga.pdf`). camelot's playa hands undefined ligature glyphs out as raw cid bytes, which are dropped.
  - **Nudi** (kannada): legacy 8-bit; `Nudi01e*` roman-digit and `Nudi01k*` kannada-digit converters (`Kannada-Nudi.pdf`).
  - **Aklite** (kannada masthead): legacy; one byte is named two ways by two producers (macroman `/logicalnot` vs windows `/Acircumflex` for 0xC2); the converter builds a lexer per convention and picks per run (`Aklite.pick_lexer`); only the 13 masthead glyphs are mapped, identified by rendering outlines against a `tesseract -l eng+kan` OCR (`kannada-aklite.pdf`).
  - **NudiUni** (kannada): unicode font with a broken map and no `GSUB`; `NUDI_UNI_KANNADA` is read off the regular blocks (glyph 66 consonants, glyph 102 vattus; 425-glyph subsets, `NUDI_UNI_GLYPH_COUNT`); the arkavattu is `U+0CF5` from the font's own cmap; ~8% of shaped glyphs (ligatures, vowel-sign forms) stay unread; `NudiUniKannadaGlyphs` is `ArialUniKannadaGlyphs` with `get_arkavattu()` overridden (`kannada-nudiuni.pdf`).
  - **Tamil legacy layouts** (`TAM_ELANGO_*` TAM layout, `VANAVIL*`, `Sun-TommyTamilNormal`): all `TamElango` subclasses with their own byte tables read off embedded subsets against `tesseract -l tam`. Vowel signs `ெ ே ை` are drawn before their consonant and wait for one token; `ொ/ோ` arrive as halves and are composed after the jump (`to_unicode` runs `jump_after_tokens()` before `compose_tokens()`); `ர` typed as `ா` is read back (before `ொ/ோ`); a CID embedding maps byte 0xB5 to U+03BC (`glyph_aliases`); the three layouts differ only by font name, so mixing subsets gives plausible-looking wrong tables (the Vanavil patterns exclude `TAM*`/`TAB*` faces); `ஔ/ௌ` unmapped (`tamil-tamelango.pdf`, `tamil-vanavil.pdf`, `tamil-tommy.pdf`).
  - **Unicode fonts needing a repair + reorder, not a decoder**: `TAUElangoPanchali` (`tauelango_glyphs`, `TAU_ELANGO_PANCHALI`, deliberately not held to a glyph count: truncated subsets keep numbering), `Uni-Ila.Sundaram` (`ilasundaram_glyphs`, first glyph of a cluster gets the whole cluster), `TAU-Marutham` (`marutham_glyphs`; re-encoded per subset, fixed by glyph id, includes simple-font embeddings with no map via `fix_simple_font`), `Meera` and `FreeSerif` (malayalam; `meera_glyphs` / `freeserif_glyphs`; per-subset re-encoding, glyphs keyed by outline signature `MEERA_OUTLINES` / `FREE_SERIF_OUTLINES`; FreeSerif's mPDF gives private-use codepoints; `langs/malayalam.CONJUNCT_TOKENS`), `NATS` (telugu, `nats_glyphs`; first-cluster-decides map; `NATS` table checked against the font's own `GSUB`; vattus reordered in front of marks).
  - **Remaining kannada/telugu limit**: pdfminer inserts a space inside words after zero-width vattus (`ಭೂಸ್ವಾ ಧೀನ`, `గ్రా మ`) - 16-30% of words; `-wm` does not fix it.

### Broken-`ToUnicode` repair
`Main.repair_tounicode` (in `Main.__init__`, before anything reads the PDF, so pdfminer and camelot both see it): `indic2unicode`'s `ToUnicodeFixer` (`tools/fix_tounicode.py`, import guarded) rebuilds a map from the embedded font (subset `cmap`, `uniXXXX` names, `GSUB`, plus per-font hand tables), writing a repaired copy to `cache_pdf/<run_id>/tounicode/`; `self.pdf_path` points at it.
- Affected: `Arial Unicode MS`, `Nirmala UI` (incl. `,Bold`, folded by `font_lookup_key`), `Mangal` (holes `<0000>`, repaired from `MANGAL_OUTLINES` keyed by glyph outline signature, because the producer renumbers glyphs per subset), Type3 fonts, and the families above. Repaired text is correct but in drawn order, so `get_repaired_font_res` points those fonts at the reordering `*_glyphs` converters (prepended to `indic_font_res`); their regexps match the **whole** font name (`^(?:.{6}\+)?<name>$`) and are built on the name the pdf carries (`fixed_font_names`), because e.g. `TAUElangoPanchali-SC700` has a sound map and must not be reordered.
- `ToUnicodeFixer.glyph_strings` shares a glyph's string between subsets only when both number their glyphs alike (`glyph_count`); outlines can't decide that (bold vs regular differ in outline but share numbering). A font with an outline table is repaired only when its map has holes (`has_map_holes`; a Mangal with the shaping-slip fault was made worse by a partial repair, `sebicirculars4.pdf`).
- **Fonts with a stripped dictionary name** (`/CIDFont+F1`): looked up by the name the font program gives itself (`program_name`, `recover_font_names`), only when the pdf's own name places nothing and the recovered name is a known broken family (`tamil-unknown.pdf`; `judgment50`/`lsdebate` Nirmala subsets numbering 5025 glyphs are left alone because `NIRMALA_UI_GLYPH_COUNT` is 4309).
- **Tables that must hold to a numbering**: `NIRMALA_UI_KANNADA` is keyed by glyph id and `BROKEN_FONT_GLYPH_COUNTS` (`NIRMALA_UI_GLYPH_COUNT = 4309`) drops a hand table for a subset with another `numGlyphs`; Arial Unicode MS has never turned up in a second numbering. Kannada Arial Unicode MS / Nirmala UI add glyphs the map leaves out (`add_missing_glyphs`, `ARIAL_UNICODE_MS_KANNADA` blocks, `NIRMALA_UI_KANNADA` 15 glyphs per consonant); a vattu is written virama-first, a dead consonant virama-last, the arkavattu marked with a ZWJ (`ARKAVATTU_MARK`) that `fonts/kannada/arialuni.py` drops again.
- **Simple fonts and maps**: `fix_simple_font` repairs embeddings with no map (`byte_glyphs` reads byte -> glyph from the subset's own cmap); `RE_ENCODED_FONTS` (`TAU-Marutham`, `Meera`, `FreeSerif`) means nothing a subset says about its own glyphs is believed; `build_cmap(codebytes)` writes a 1-byte codespace for simple/Type3 fonts (playa honours it, pdfminer doesn't; fixed `tamil-marutham.pdf` bordered-table tamil); `glyph_order()` gives nameless fonts names of the module's own making (mPDF's odd-length cmap subtable isn't decompilable by fontTools); an `akhn` substitution ending in a virama is a pre-reordered telugu/kannada cluster (`VIRAMAS`, `virama_of`).

### Font detection from the text (`Main.detect_unknown_fonts`)
Runs on the parsed XML between `drop_overlapping_spaces()` and `convert_indic_fonts()` (on text as drawn). Every font that neither its name, a `-fc` mapping nor the repair placed is classified by the `machinelearning/` model; a placed font is registered as a regexp in `indic_font_res` exactly like a `-fc` mapping (detected entries go in front; `-fc` wins).
- **Class -> converter** via `FONT_CLASS_CONVERTERS` (only where label and key differ: `nirmala` -> `nirmalaui`); `not_required` and `type3` are taken as is; `FONT_CLASSES_WITHOUT_CONVERTER` = `mangal, nudiuni, tauelango, ilasundaram, marutham, meera, freeserif` (and `type3`): the repair places them, no decoder exists, so a verdict changes nothing and these fonts are skipped **before** classification where recognisable (by name through `FONT_DETECT_NO_CONVERTER_RE`; `type3` by reading the repaired pdf with pymupdf via `get_type3_font_names()`: a Type3 font the repair found nothing to fix has correct text, and a retrained model called it `arialuni` at 1.00 and the lossy decoder destroyed it in `union_hindi5.pdf`).
- **Text is collected per font as runs joined with a space** (not one concatenation: the spaces between words belong to no font).
- **A verdict is checked against the text** (`get_detected_font_key`, `FONT_CLASSES_INDIC_TEXT`, `INDIC_SCRIPT_RE`, `FONT_DETECT_MAX_INDIC_RATIO`): every class except those already drawing indic text (`arialuni`, `nirmala`, `type3`, `tunga`, `nudiuni`, `tauelango`, `ilasundaram`, `marutham`, `meera`, `not_required`) is a legacy encoding overloading *latin* codepoints, so > 5% indic text makes the verdict impossible and the font is left alone with a warning (the model called `lsdebate.pdf` `CIDFont+F1` `chanakya` at 1.00). A class not named is assumed latin-source; name a class there as soon as its font is known (`marutham` was missing and was rejected wrongly).
- **Standard latin faces are whitelisted out** (`FONT_DETECT_SKIP_RE`: `times|arial|calibri|cambria|courier|helvetica|verdana|tahoma|garamond|book antiqua|bookman|liberation|nimbus|myriadpro|minionpro|segoe|malgun|yu gothic`, matched anywhere in the name, case-insensitive; TeX Computer Modern `(?:^|\+)cm[a-z]{1,6}\d+` anchored; `FONT_DETECT_SKIP_EXCEPT_RE` = `arial[\s_-]*unicode` carves Arial Unicode MS back in). The check sits after the `get_indic_font_key()` lookup so a repaired font never reaches it.
- **Thresholds**: `FONT_DETECT_MIN_WORDS` 20 (confidence collapses on short samples: 5 words scored 0.81 for the wrong class), `FONT_DETECT_MIN_PROB` 0.5, `FONT_DETECT_MAX_WORDS` 20,000 cap. Below either, text is left as drawn. A decoded-wrongly font destroys text; a wrongly left-alone font only loses the improvement.
- The model (Orange, ~1 s import) loads lazily on the first document with an unplaced font; a failed load is remembered; missing model/failure degrade to "leave the fonts as they are", never an exception. `-fn` reports the model's answer **as it stood** (`data-detected-font`), even when rejected.
- Validated on `union_hindi.pdf` (its `-fc TT572t00=chanakya,TT447t00=chanakya` mapping was removed from `test_cases.csv`; both fonts detected at 1.00 as `krutidev`, byte-identical output).
